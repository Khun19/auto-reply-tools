# V0.3 — Notification Engine: Gap Analysis

## Scope

V0.3 is limited to receiving Viber notifications, converting eligible notifications into `AutomationTask`, and handing them to the existing automation queue. AI UI automation and response handling remain later milestones.

## Requirement audit

| Requirement | Existing implementation | V0.3 action |
| --- | --- | --- |
| Register `NotificationListenerService` | `ViberNotificationListenerService` is registered in the Android manifest | Verify on device |
| Viber package filter | `com.viber.voip` | Covered by pure policy test |
| Ignore group summaries | `Notification.FLAG_GROUP_SUMMARY` | Covered by pure policy test |

| Extract message | `EXTRA_BIG_TEXT`, then `EXTRA_TEXT` fallback | Covered by policy behavior |

| Duplicate guard | Existing SHA-256 fingerprint + bucket + cooldown | Covered by unit tests |
| Enabled safety gate | Existing `AutomationEngine.enqueue()` settings check | Existing implementation; device verification remains |
| Queue handoff | Existing `AutomationEngine.enqueue()` | Verify on device |
| Automated test evidence | Previously missing notification-specific unit coverage | Added in V0.3 |

## Gap closed

The material V0.3 code paths already existed at the V0.2 baseline. The missing engineering evidence was isolated, deterministic notification-policy tests. The notification acceptance rules are now centralized in a pure policy object so they can be tested without an Android device, while the listener retains Android-specific notification and `PendingIntent` handling.

## Acceptance boundary

V0.3 is ready for the project gate only after:

1. `./gradlew test` passes in the Android project.
2. The APK builds successfully.
3. On a real Android device/emulator with Viber installed, a Viber notification from a whitelisted sender produces one automation task.
4. Non-Viber notifications, group summaries, blank notifications, non-whitelisted senders, duplicates, and disabled automation do not produce a task.
5. Conversation intent/identity is retained for the later Viber-open step.

Per the project milestone rule, V0.4 must not begin until the user explicitly reports **V0.3 PASS**.
